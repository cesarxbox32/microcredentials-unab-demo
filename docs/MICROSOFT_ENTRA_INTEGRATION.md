# Identity Manager, Entra ID y Microsoft Graph

El adaptador limita el alcance a grupos configurados mediante UUID y dominios permitidos. Usa OAuth 2.0 `client_credentials` con `https://graph.microsoft.com/.default`. La consulta solicita `id,displayName,mail,userPrincipalName,accountEnabled` a `GET /v1.0/groups/{id}/members/microsoft.graph.user` con consistencia eventual y paginación validada. Deduplica por ID y correo. Si Graph omite `accountEnabled`, devuelve estado desconocido. [Microsoft Graph](https://learn.microsoft.com/graph/overview) · [Identidad Entra](https://learn.microsoft.com/entra/identity/) · [Miembros de grupo](https://learn.microsoft.com/graph/api/group-list-members) · [Flujo de credenciales](https://learn.microsoft.com/entra/identity-platform/v2-oauth2-client-creds-grant-flow)

## Permisos y alcance

- `GroupMember.Read.All` es el permiso de aplicación mínimo de la operación de listar miembros. Graph devuelve información limitada cuando falta el permiso para leer un tipo. Validar `User.Read.All` en piloto si se necesitan atributos de cuenta ausentes, con consentimiento administrativo. Mantener cualquier cuenta de estado desconocido en revisión. Evitar `Directory.Read.All` como base y excluir grupos ocultos del piloto. La lista de grupos de la app limita su comportamiento y el consentimiento de Graph conserva su propio alcance. [Permisos de Graph](https://learn.microsoft.com/graph/permissions-reference)
- `Mail.Send` permite `POST /v1.0/users/{id}/sendMail`. Aprobar una identidad de aplicación distinta y limitar el envío al buzón autorizado en Exchange. HTTP 202 indica aceptación de la solicitud. La entrega exige verificación independiente. [Enviar correo](https://learn.microsoft.com/graph/api/user-sendmail) · [RBAC de aplicaciones en Exchange Online](https://learn.microsoft.com/exchange/permissions-exo/application-rbac)

## SSO, aprovisionamiento y sincronización

Configurar la aplicación empresarial SAML con metadatos y valores entregados por Coursera. Validar Entity ID, Reply URL, certificado, identificador estable, claims y grupos asignados con una cuenta piloto. El SSO autentica a la persona. La activación de una membresía educativa depende del flujo de invitación y del contrato. Si Coursera habilita SCIM u otro aprovisionamiento para el plan, documentar mapeos y bajas con el representante. El código no presupone soporte SCIM en Coursera. [SSO SAML](https://learn.microsoft.com/entra/identity/enterprise-apps/add-application-portal-setup-sso) · [Aprovisionamiento](https://learn.microsoft.com/entra/identity/app-provisioning/configure-automatic-user-provisioning-portal)

Persistir en producción el par tenant–object ID, el ID externo de Coursera y la fecha de sincronización. Resolver colisiones con revisión humana. El adaptador Python devuelve identidades elegibles para importación. Falta conectarlo a un flujo institucional de importación, persistencia del vínculo y gestión de bajas. En la demo se registra una sincronización ficticia y los dominios son configurables dentro de `.example`.
